# Generating Candidates

How to produce names worth checking. The difficulty is specific: the names that sound best for a category are the ones already taken, because everyone describing a similar product reaches for the same words, and so does every model they ask.

## Before Generating

- Complete the brief, including its taste item: what the person has liked and rejected and why, and anything the name must contain. One reaction, such as a name that sounds like the wrong kind of brand, steers better than any amount of description
- Ask whether the name should explain itself or be given its meaning by the product, because a name of the other kind rarely satisfies
- Put the name in use now in the set. It gets the full check like the rest, and every candidate is measured against it

## Where Names Come From

- **Go past the first names that come to mind:** The obvious, confident name sits where every other model lands too. Confidence is a sign of crowding, not of quality. Do not drop such a name on that suspicion, and do not present it as a find either. Check it
- **Spread across kinds of name:** Plain compounds of two ordinary roots, coinages built on a recognizable root, real words that are rare or old, words from another language of the market, short phrases, and names made up from nothing. Names built from real roots say something about the product. Made-up names say nothing and clear the registers most easily. Neither is better, so spread across both until the person has said which they want. Rare real words can arrive with a dictionary sense, a sound-alike, or a resale price attached
- **Build from the product's own specifics:** What it does that others do not, the moment it is used, the object or gesture at its center. Category words such as the field's name and its obvious verbs are the crowded ones
- **A reachable name is not a spoiled one:** That another person could arrive at the same name is a reason to check the registers harder, where registration dates and suffix spread show whether anyone acted on it. It is not a reason to drop the name

## What To Present

- A candidate is a name that has been checked. Present candidates with both results, their addresses, and what the addresses cost, so a name can be registered the moment it is chosen
- Drafts you discard before showing anyone were never in play. Discard for fit to the brief and the person's stated taste, never on a guess that a name is taken and never on one lookup, such as a registered `.com`
- A raw list is allowed only when the person asks for one or has no direction yet. Give every name in it its fit result and the line saying what the name is, label the whole list unchecked for clearance, describe nothing in it as available, and check the names they react to first
- Generate a set the session can check in full over one it cannot. When the person asks for a large set, generate it, say what checking it will cost, and report coverage exactly

## When A Loved Name Is Taken

A person usually recognizes the feel they want before any name clears. When a name they love comes back Avoid, do not go back to a blank page. Generate its neighbors: the same root with another ending, the same rhythm, the same idea one step over. Check them before showing them. A neighbor keeps the feel the person already chose, so try neighbors before a fresh list.

## Rounds

Names are found by reacting, not by one large list. After each round ask which names the person would say aloud and which they would not, and why, then generate the next round around those reactions. Keep every checked result from earlier rounds in the table, so nothing is checked twice and a name that returns is recognized.

Stop when the person prefers a candidate to the name in use now, they are happy with how it sounds, and it is Clean, Fine, or a Caution whose size and open question they accept. If nothing beats the current name after real rounds, say so plainly. Keeping it is a result.
